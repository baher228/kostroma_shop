# Автоматическая запись и управление всеми магазинами

Ручной запуск записи удалён из приложения. Продавец больше не видит вкладку
«Запись», кнопки управления и локальную историю. В панелях администратора
остались только автоматическая запись по речи и её включение/выключение.

Миграция `019_audio_qc_vad_only.sql` однократно переводит существующие политики
в `vad_auto` с `enabled=false` и создаёт выключенные политики для назначенных
планшетов. Повторный запуск мигратора не сбрасывает последующие настройки.
Политика по умолчанию также выключена и использует VAD. Исторические данные
о ручных записях и фактический режим в диагностике сохраняются.

Старые приложения получают политику при следующем успешном опросе (интервал
45 секунд в активном приложении). Офлайн-устройство нельзя считать получившим
команду. После получения `vad_auto` старый экран скрывает ручной запуск.
API отклоняет новые ручные команды и ручные сессии планшетов с закэшированным
экраном. Для записи нужен Android APK с native VAD module и разрешение ОС
на микрофон; серверная политика не выдаёт это разрешение.

В веб-панель добавлен пункт «ВСЕ МАГАЗИНЫ». Общая история сохраняет пагинацию,
период и название магазина в каждой строке; статистика и динамика запрашиваются
без фильтра по магазину. Групповые настройки применяются только кнопкой
сохранения. Запись для всех магазинов не включается при выборе общего вида.
Групповая команда сохраняется одним SQL-оператором и доступна только менеджеру.

Планшеты записывают локально. Сервер принимает до двух загрузок одновременно;
при занятости клиент получает 429 и повторяет отправку. У сервера есть
постоянная очередь PostgreSQL с повторными попытками и блокировкой задач.
В текущем процессе один обработчик выполняет задачи последовательно.
Число одновременно записывающих магазинов не равно числу параллельных
AI-заданий. Предельную устойчивую нагрузку без замера на реальных записях
оценить нельзя; перед включением всей сети нужно следить за возрастом очереди,
скоростью её обработки, объёмом хранения и лимитами AI-провайдеров.

Перед релизом проверены авторизованные GET-запросы основных RU/Dubai API,
детализация AI-сессии, общая история и статистика. Nexara и GigaChat отвечают
на запросы моделей, MinIO доступен. Это проверка доступности и авторизации,
а не массовая нагрузочная проверка или новый платный прогон распознавания.

Из команд сборки удалён добавленный в основной ветке обфусцированный `init`,
а app.config.js восстановлен без внедрённого хвоста. Проверка конфигурации
также запрещает повторное подключение этого загрузчика из package scripts.
Локальные `.env` снова исключены из Git.

Визуальная проверка через открытый Firefox не завершена: подтверждение доступа
к окну истекло. Компоненты проверены рендерингом, типами и production-сборкой.
